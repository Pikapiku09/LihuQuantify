## 二、关键发现清单（按对决策的影响排序）

### 2.1 决定变量不是单票上限，是「同时拿几只」✅

| 组合 | p95 最大回撤 | 中位权益 |
|---|---:|---:|
| K=1（满仓单票） | **48.4%**（破 25% 线） | 14.16 万 |
| K=3（cap 20%） | 16.7% | 13.63 万 |

- K=1→3：**用 0.52 万中位收益换掉 31.6pp 尾部回撤**
- cap 15%→20%：p95 回撤仅 +3.65~3.98pp，中位权益仅 +0.43~1.24 万
- 计入同涨同跌（ρ=0.8）后：**只有 4/12 组合仍过 25% 线**，cap 20% 时 p95 升到 28.5% **破线**
- ⚠ 局限：经验分布来自你**自己**的 122 波，样本小、单一市况、独立抽样**偏乐观**

### 2.2 你确实在挑好公司，但这不影响盈亏 ✅

买入时的全市场横截面分位（中位）：

| 维度 | 分位 | 判定 |
|---|---:|---|
| 市值 | **93.3%** | 只买前 7% 的大票 |
| ROE | **82.1%** | 强烈偏好高 ROE |
| 营收同比 | 79.6% | 偏好高增长 |
| PB | 76.2% | 偏好**高估值** |
| 净利同比 | 72.6% | 偏好高增长 |
| PE | 40.5% | 偏低（增长摊薄） |

**但盈利波与亏损波在这 6 个维度上 p 全部 >0.24。** 偏好是真的，收益贡献是零。

### 2.3 唯一有解释力的：买入后有没有立刻涨 ✅

| 特征 | Cliff's δ | OOS δ | FDR |
|---|---:|---:|---:|
| 进场涨幅（事后变量） | +0.625 | +0.647 | 0.000 |
| 买入后 5 日涨幅（**实时可得**） | +0.463 | +0.528 | 0.001 |

分档（面板口径，已复算）：`0~2%` 共 **21 波、胜率 9.5%**；`>10%` 胜率 80.6%。

### 2.4 但把它做成规则会亏钱 ✅（这条最反直觉）

「第 5 日仍为负就离场」在真实交易上反事实：**Δ −22,705 元，胜率 61.8%→47.4%**。
机制：触发的 43 笔里 **19 笔最终赚钱**（+20,153）被砍在低点，而最大亏损波（−16,364）**根本没触发**。
→ 「5 日涨幅」能**判断**一笔交易好不好，但**不能**当**离场触发器**用。

### 2.5 消息面、财报新鲜度、入场特征：全部不可过滤 ✅

| 检验 | 结果 |
|---|---|
| 业绩预告（临近 120 日内有无） | 58.3% vs 53.1%，Fisher **p=0.82** |
| 财报公告新鲜度 | 中位 53 天，各档胜率 41~57%，**无单调** |
| 13 个「买入日可见」入场特征 | **BH-FDR 后 0 个显著**（最小 q=0.62） |

### 2.6 真正有区分度的其实是「品种」❓

ETF 胜率 **69.2%** vs 个股 **47.0%**（Fisher p=0.032）——但与买入时期严重混杂
（2024-25 胜率 75.5%，2026 仅 39.7%），**不能当入场规则**，需另做时期中性化才能下结论。

### 2.7 账户级真实绩效：赢了大盘 3.5pp，代价是 3.4 倍波动与一次 −40% 回撤 ✅

用 905 笔真实成交重建日级权益（26 个月 / 504 个交易日）：

| 指标 | 数值 |
|---|---|
| 累计 / 年化 | **+12.42% / +5.82%**（同期上证 +8.93%） |
| 月度胜率 | **53.8%**（14 涨 / 12 跌） |
| **最大回撤** | **−39.75%**（剔除估值跳变后 **−34.80%**），2025-09-25→2026-08-03，**312 天未修复** |
| 与上证相关 | Spearman **+0.6485** |
| 月波动 | 账户 **12.26%** vs 大盘 3.59% → **3.4 倍** |

**月度盈亏由 2~3 只重仓票单独决定：**
- 2026-05：当月**胜率 70%**，却因春风动力单只 **−28,095** 而亏 **−23.69%**
- 2026-07：凤凰航运 **−21,236** → 当月 −19.40%
- 2025-08：福达/德赛/春风 → 当月 **+25.16%**

> 口径：110000 为假设初始资金，但期初 7 只无买入记录的持仓按首日收盘计值 104,781.50 元（占 95.3%），
> 与该假设自洽；不含天天宝/银证转账，故现金项可为负（「现金+持仓市值」恒等式成立）；行情为原始价未复权。

### 2.8 2.1 与 2.7 互相印证 ✅

集中度测算给的 **K=1 时 p95 回撤 48.4%**，与账户实测 **−39.75%** 同一量级——
说明当前持仓方式确实接近 K=1~2，**风险几乎全部来自「押得少、押得重」**，不是单票上限。

### 6.1 两侧地基（实测）

| 项 | LihuQuantify | dsh-invest |
|---|---|---|
| 框架 | FastAPI + uvicorn | Cordis 插件（Node 22） |
| 端口 | **自监听 8000** | **不自监听**，45 条路由寄生 DSH 端口 |
| 路由 | 16（14 GET + 2 POST） | 45 条，全部 `kind:exact` |
| 页面 | 7 个（单文件原生 JS，无构建） | 8 视图 / 7 侧栏入口 |
| 数据 | DuckDB 17 表（**9 张空**）+ JSON | SQLite 投影 + 20 个 JSON/JSONL |
| 鉴权 | 可选共享 Bearer，仅覆盖 `/api/*` | loopback-only（`Host` 头校验） |
| 可达性 | 127.0.0.1:8000 | 仅 loopback |

### 6.2 一个能直接排除方案的硬约束

**Lihu 前端把 `/api/` 与 `/static/` 全写成根绝对路径（实测 10 处）。**
一旦挂到 `/lihu/` 前缀下，浏览器会把 `/api/*` 发到 DSH 的根 → **全站 404**。
`<base href>` 救不了，只能改 Lihu 源码或改写响应体（对 1MB bundle 不可行）。
→ **方案 2（反向代理）被排除**，除非愿意改 Lihu 前端。

### 6.3 推荐：方案 1（iframe 嵌入）

**理由**：dsh-invest **自己就是用 iframe 把工作台塞进 DSH 主面板的**
（`packages/dsh-invest/lib/client.js:77,92`，`WB_URL = "/dsh-invest/app"`）——
这条路在本仓库是「既有工序」，不是新架构。

另一个容易被高估的风险：**「iframe 只能 loopback」不是新增限制**。
`isLoopbackRequest` 今天就会对非 loopback 的 `Host` 返回 403，两侧可达性包线完全相同，加 iframe 不收窄任何东西。

### 6.4 冲突清单（C 的结论，与我的预判有出入）

| 冲突 | 严重度 | 结论 |
|---|---|---|
| **持仓账本撞名** | 🔴 高 | **实际不真撞名**：Lihu 全仓**没有** `持仓.json`，`paper_state*.json` 是 5 本模拟盘；dsh 的是实盘对话账本。两者结构不兼容（dict vs array、`volume` vs `shares`）。两边都硬编码「严禁混账」→ 合并必须加 `account_type` 并拒跨域写，否则实盘与模拟盘会在同一 UI 里串 |
| **行情存三份** | 🔴 高 | DuckDB 41 万行 / Lihu 缓存 2.6GB / dsh 缓存 476MB；**日期格式三种**（DATE / YYYYMMDD / ISO 文本）、复权口径不一致 |
| Tushare 取数路径 | 🟡 中 | 三条路径，dsh 两条**无缓存无限流** |
| 配置三套 | 🟡 中 | 风控 0.15→0.20 曾靠人工对齐（现已回 0.15） |
| 双运行时 | 🟡 中 | Python 3.12 + Node 22；dsh 侧无 Docker |
| 端口 | 🟢 无 | 插件不绑端口，Lihu 独占 8000，不抢 |
| Tushare token | 🟢 无 | 两处已指向同一个 `.dsh-invest/tushare.token`，是**现成的统一点** |

**额外发现**：两仓已有 **8 条跨仓硬依赖**（token 默认路径、交割单 CSV、波段池 md、NAS 推送、
提示词里硬编码的 `E:\LihuQuantify\docs\` 等）。
→ **合并的本质不是「搬迁」，是把隐性耦合改成显式接口。**
