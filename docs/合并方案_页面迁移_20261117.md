## 一、先回答：策略健康与判断质量重不重合？

### 1.1 结论：**不重合**，但有三处真实的误读风险

| 维度 | 判断质量（已有） | 策略健康（新增） |
|---|---|---|
| 回答什么问题 | 这套 **AI 流水线**说的准不准 | 这套**模拟盘策略**健康不健康 |
| 被测对象 | dsh-invest 各角色的结论 | LihuQuantify 的模拟盘账户 |
| 数据源 | `.dsh-invest/store/conclusions.jsonl` | Lihu 导出的契约快照 |
| 时间口径 | 结论日后第 **5/20 个交易日**收盘 | 快照时点 + 近两年账户全量 |
| 核心指标 | 命中率 / 盈亏比 / 期望值 / **置信度校准** | 回撤 / 集中度 / **行为偏差** / 研究判决 |
| 谁产生的 | AI 说的 | 机器执行的 |
| 判断的是 | 观点质量 | 执行与风控质量 |

一句话：**判断质量测「嘴」，策略健康测「手」。**

### 1.2 但你的担心有根据 —— 三处会打架的地方

| # | 风险 | 具体表现 |
|---|---|---|
| 1 | **名字同味** | 「判断**质量**」「策略**健康**」都是在评价好坏，用户扫一眼分不清谁评谁 |
| 2 | **指标撞名** | 两边都有「**胜率**」：一个是 AI 结论命中率，一个是模拟盘交易胜率。同屏看到两个不同数字会怀疑系统算错 |
| 3 | **都出现「回测」** | 判断质量页里本来就有「回测口径」字样；Lihu 还有个「回测分析」页要迁进来 → 三个「回测」 |

### 1.3 三条防误读设计（建议一并做）

1. **页面级边界声明**：每页标题下一行固定句式
   - 判断质量：「本页只评 AI 结论的准确度，**不评价策略盈亏** → 策略表现见「策略回测」」
   - 策略健康：「本页只评模拟盘的风控与行为，**不评价 AI 判断** → 判断准确度见「判断质量」」
2. **指标名一律加限定词**：`结论命中率` / `交易胜率`，禁止裸写「胜率」
3. **互相交叉链接**：两页各放一个跳转按钮

## 二、Lihu 的 7 个页面：该迁哪些

### 2.1 全景对照

| # | Lihu 页面 | 实际内容 | dsh-invest 现状 | 建议 | 价值 |
|---|---|---|---|---|---|
| 1 | 仪表盘 | 指标卡 + 今日简报 + **回测**权益曲线 | 概览/持仓工作区（都是**实盘**） | ✅ **迁**，改名「模拟盘总览」 | 高 |
| 2 | 巡检报告 | 55 份每日巡检日报 | 运行记录（AI 流水线报告，不同物） | 🔀 **折叠**进策略健康页 | 中 |
| 3 | 回测分析 | 回测绩效（收益/回撤/胜率/交易数） | 无 | ✅ **迁**，必须改名 | 高 |
| 4 | 波段池 | 三年回测 + 当前池子 + 稳健性 | 无页面（只有 P_SWING 角色） | ✅ **迁** | **最高** |
| 5 | 网格搜索 | 参数网格摘要 | 无 | 🔀 **折叠**为回测的二级 tab | 低 |
| 6 | 市场热力图 | 板块/个股热度 | 无 | ⏸ **暂不迁** | 中 |
| 7 | 系统设置 | 策略参数写入 | 模型设置（不同物） | ❌ **不迁** | — |

### 2.2 为什么这样排

**「波段池」优先级最高**：这是你最初问题的起点（周报邮件还发着中航沈飞）。它现在完全没有工作台入口，只能靠邮件和 md 文件。而且数据现成：`/api/swing_backtest`（三年回测 + 蒙特卡洛对照）、`/api/swing_pool`（当前持仓 md）。

**「系统设置」坚决不迁**：它是 Lihu 唯一的写接口（`POST /api/settings`，会写 `settings.yaml` + `secrets.json`）。搬进工作台就制造了**双写风险**，正是 C 勘测警告的那类。策略参数留在 Lihu 改，工作台只读展示关键值——这件事策略健康页已经在做了（显示 cap 0.15 / 持仓下限 3）。

**「网格搜索」不该单独成页**：它是研究副产品，一年点不了几次，而且 Lihu 自己在页面上都标了「训练段参考·含幸存者偏差」。做成回测页的二级 tab 足够。

**「热力图」暂缓**：需要 Lihu 侧的行情/板块数据，跨仓成本最高，收益最不确定。

## 三、一个必须先补的地基缺口

### 3.1 模拟盘权益历史根本没有持久化

这是本轮查证里最重要的发现：

| 事实 | 位置 | 后果 |
|---|---|---|
| Lihu 的 `/api/equity` 读的是 `outputs/backtest_result.json` | `web/server.py:386` | 页面上那条「权益曲线」是**回测**曲线，不是模拟盘真实权益 |
| 模拟盘账户没有日级权益落盘 | `drawdown_note` 已标注 | 策略健康页的 `current_drawdown` 只能是 `null` |
| `paper_state.high_water_mark` 是**每只股票**的价格高点 | `{"000429.SZ": 13.78}` | 拿它算组合回撤会得出假数 |

**也就是说：现在工作台里没有任何一条「模拟盘真实权益曲线」可用。**

### 3.2 好消息：重建逻辑已经写好了

上一轮 `fill-analyzer` 用 **905 笔真实成交**重建出了日级权益（`scripts/monthly_perf.py` → `outputs/monthly_perf.json`，26 个月、504 个交易日，含 `−39.75%` 最大回撤与估值跳变标注）。

**把这份逻辑改成每日追加一行 `data/equity_history.jsonl` 即可**，一举三得：
1. 填掉 `drawdown_note` 缺口
2. 支撑「模拟盘总览」的权益曲线
3. 让回撤告警变成实时（而不是快照时才估）

## 四、契约扩展：v1 → v2

现有 v1 只有 `strategy / risk / behavior / research / findings`。要支撑新页面，建议扩到 v2：

| 新块 | 内容 | 支撑哪个页面 |
|---|---|---|
| `equity` | 日级权益序列（最近 250 交易日）+ 当前回撤 + 最大回撤区间 + 估值跳变标注 | 模拟盘总览、策略健康 |
| `backtest` | 回测绩效摘要（总收益/年化/MDD/夏普/胜率/交易数/区间） | 策略回测 |
| `swing` | 当前池子（md 原文 + 解析后的表）+ 三年回测 + 蒙特卡洛分位 | 波段池 |
| `reports` | 最近 10 份日报的索引（日期/标题/摘要行） | 策略健康（折叠） |

**版本策略**：`schema_version: 2`，工作台按版本分支渲染；v1 数据仍能读（降级为只显示原有四块）。**不允许**在 v1 里偷偷加字段——那正是原来那套「裸读、字段一改静默空白」的毛病。

## 五、分期计划

| 期 | 内容 | 工期 | 产出与验收 |
|---|---|---|---|
| **P0** | 权益历史持久化（每日追加 jsonl）+ 契约 v2（先只加 `equity`） | 0.5 天 | 策略健康页显示**真实**回撤曲线，替掉 `drawdown_note` |
| **P1** | 「模拟盘总览」页（指标卡 + 权益曲线 + 今日简报） | 1 天 | 取代 Lihu 仪表盘；与「持仓工作区」明确区分模拟盘/实盘 |
| **P2** | 「策略回测」页（绩效 + 交易分布 + 网格折叠 tab） | 1 天 | 迁入 Lihu 回测分析；顶部加边界声明 |
| **P3** | 「波段池」页（当前池 + 三年回测 + 稳健性） | 1~1.5 天 | **优先级最高**，直接替代周报邮件 |
| **P4** | 巡检报告折叠进策略健康 | 0.5 天 | 最近 10 份摘要 + 展开 |
| **P5** | 市场热力图 | 2 天 | 可选，暂缓 |

**合计约 5~6 个工作日**（不含 P5）。页面数 8 → 11。

### 建议的执行顺序理由

P0 必须先做：没有真实权益序列，P1 画出来的曲线还是回测数冒充实盘，等于把刚修的坑再挖一遍。

P3 建议提前到 P1 之后：它是你真实痛点（周报还在发旧标的），而且数据完全现成，不依赖 P0 的权益历史。

**所以更优顺序：P0 → P3 → P1 → P2 → P4。**

## 七、明确不做

| 项 | 原因 |
|---|---|
| 迁「系统设置」 | Lihu 唯一写接口，搬过来就是双写；策略参数留原处改 |
