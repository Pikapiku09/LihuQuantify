## 2. 复现方法与口径设计

### 2.1 唯一统计入口

```python
from lihu_quantify.monitor.review_progress import review_stats   # 唯一统计入口
from lihu_quantify.backtest.metrics import _pair_rounds           # 唯一 FIFO 配对实现
```

`review_progress.py` 模块头注释原文（第 4 行）：**"本模块是唯一统计入口，禁止另写配对算法。"**
本次重算**只 import 复用**，没有复制任何配对逻辑。

### 2.2 两种段归属口径（都必须有，缺一就会讲错故事）

| 口径 | 做法 | 性质 | 用途 |
|---|---|---|---|
| **A 按平仓日归属** | 对每个段尾日期做 `_pair_rounds(trades[:date < 段尾])` 前缀差分；段轮次 = 前缀差 | 各段之和**精确等于**全量（可对账） | 对账、看时间轴 |
| **B 全段内样本** | 先按 `[段起, 段止)` 切成交，再 `_pair_rounds` | 只保留"开仓与平仓都在同一版本段内"的轮次 | 判断**归因**、识别净有效样本 |

**为什么 A 不能用于归因**：口径 A 里一段的"盈利改善"可能只是上一段建仓的仓位在本段平仓，
与本次的代码改动毫无关系。§6.4 会给出一个这样的实例。

**为什么 B 会少轮次**：跨段配对（上一段买、下一段卖）被口径 B 排除。
本次 464 轮中，176 轮是跨段的（wbr25 101 + main 24 + ir20 16 + s43 16 + s44 19），口径 B 保留 288 轮。

### 2.3 前缀单调性自校验

`_pair_rounds` 按 `trade_date` 升序逐笔处理，追加更晚的成交只会**追加**新的轮次，不会改写已算出的轮次。
脚本里对此做了断言校验（`cum[i]` 必须是 `cum[i+1]` 的前缀），五账本全部通过；
且各段轮次之和与 `review_stats` 全量 `closed_rounds` 逐账本精确相等。【实证】

## 6. 关键读数怎么读（避免自欺）

### 6.1 main 的 E1b 是"因子方向反"的教科书样本

12.77% 胜率 + 3.568 盈亏比 = **方向错、靠右尾撑盈亏比**。
胜率低到 1/8，但盈亏比 3.5 让人误以为"策略只是运气差"；
实际 EV 仍有 −103.7 元/轮，与 pooled E1b（224 轮 / 20.98% / −96.5 元）同向。
这与第十二轮报告 §4.1「低分位 −25.18% vs 高分位 +13.39%」的方向一致。【实证 + 复核】

### 6.2 E0 的 CherryClaw 表现比 IR 旧版更好，不代表 CherryClaw 更好

E0 pooled 64 轮 / 43.75% 胜率 / **+46.3 元/轮为正**，而 E1b 是 20.98% / −96.5 元。
**但这段差异不能归因于策略优劣**：E0 是 2026-08-26~09-25 的市场环境，
E1b 是 09-29~10-22 的下跌段，样本量与市场环境完全不同，属于混淆变量。
`docs/papers/CherryClaw复盘报告.md` 与 `docs/决策日志_待决策_CherryClaw处置.md` 的样本外结论是
CherryClaw 成本后年化 −5.92%（零费 −3.29%），两者不矛盾——E0 只有 64 轮、约 1 个月。【实证 + 复核】

### 6.3 s44 总盈亏 +9,003 元是怎么来的

s44 的 +9,003.40 元**全部来自 E0（+8,590.74）与 E1c（+6,208.06）**，
中间 E1b 亏 −5,795.40。而 E1c 的 +6,208 只有 15 轮、口径 B 只有 5 轮全胜。
**用一个 5 轮全胜的样本得出"cherry_claw + block 很强"是典型的过拟合叙事。**【实证】

### 6.4 口径 A 的 E1c "改善"不能归功于 block 闸门

口径 A 里 IR 系 E1c = main 25 + ir20 22 = 47 轮，胜率 28.00% / 40.91%，看起来比 E1b 好很多。
但口径 B 显示：main 只有 9 轮、ir20 只有 6 轮是真正在 block 期内建仓并平仓的。
那 47 轮里的大部分是 **E1b 建仓、E1c 平仓**，而 10-23 之后市场恰好有一波反弹，
把旧仓位救回来了。**这是市场给的，不是闸门给的。**（对照 §1.1：block 期几乎没开新仓）

### 6.5 一个必须记录的推论

看板 `98/100` 的分子分母口径本身没写错（`review_stats` 算得没错），
错的是**读者假设**：看到 98/100 就以为"当前策略快可以评审了"。
真实情况是：当前代码版本（E2）的有效样本是 **0**。

## 8. 局限与待核实

| 项 | 说明 | 标注 |
|---|---|---|
| 段边界按"部署日"而非"生效日" | 部署当晚的补跑可能让当日成交落在新代码下 | 【待核实】E2 边界敏感性已做，结论不变 |
| `paper_state*.json` 无版本标记 | 只能按日期推断，无法从账本文件本身确认某笔成交跑了哪个版本 | 【待核实】建议后续在成交记录里写入 `code_version` 或 `strategy_version` |
| 44 轮 wbr25 的"建仓决策时间" | 取的是买入成交日；若存在持仓重建（`stop_registry.json` 中 15 条 `buy_order_id` 为空），建仓日可能更早 | 【待核实】不影响"E2 内建仓 = 0"的结论 |
| s43/s44 策略归属 | 由代码缺省 + 信号量实证推断为 CherryClaw；账本文件本身未记录策略名 | 【实证/推断】建议在 `paper_state*.json` 写入 `strategy` 字段 |
