## 一、总评

这是一个**研究纪律远超个人项目平均水平**的量化系统：三级门禁、`n_trials` 预算、决策日志的「数据段永久消费」规则、影子账本、PIT 池复验，都是真做过的，不是文档装饰。回测口径也经历过真实纠错（滑点方向 `03bb2fe`、移动止盈公式、前复权、涨跌停建模），说明愿意为正确性付代价。

主要风险不在「研究方法」，而在**工程边界**：模拟盘 / 回测 / 实盘三口径仍有分叉；若干正确性缺陷会直接影响实盘安全（止损单丢失、除权日假止损）；web 默认无鉴权却由 Docker 映射到局域网。研究上 P7 周频因子是当前最亮资产，但策略化产物还停在未跟踪状态。

| 维度 | 评分 | 一句话 |
|---|---|---|
| 研究方法 | 8/10 | 门禁 + 决策日志 + n_trials 是真纪律 |
| 工程可维护 | 6/10 | 能跑、能改，但 scheduler 与配置漂移拖后腿 |
| 实盘安全 | 5/10 | 止损可靠性与复权口径是硬伤 |

**结论**：最值得投入的不是新因子，而是**止损可靠性、复权口径统一、web 暴露面**。P7 周频反转是很有希望的下一主线，但请先把未跟踪文件入库，策略化时用与生产一致的 `reduce` 择时和统一的池子/涨跌停规则重跑。

## 二、做得好的地方

1. **研究方法学**（`docs/因子验收单.md`、`src/lihu_quantify/research/acceptance.py`）：RankIC / ICIR / t / 单调性 / icDSR / regime 一致性硬门禁，n_trials 如实登记（累计 54），数据段消费记账——能有效防数据窥探。
2. **自我纠错文化**：CherryClaw 成本后为负就敢停用主账本；CC-Reversal 因子级增强过不了策略级 A/B 就否决；滑点方向 bug 修复后重走网格并标注口径版本。
3. **测试面**：23 个测试文件，覆盖回测 / 风控 / 执行 / 影子账本 / 看板 / AI 降级，且多数测行为而非只测 mock。
4. **运维闭环**：Docker + NAS、幂等巡检、心跳、备份、决策日志、待决策单——个人项目少见的完整度。
